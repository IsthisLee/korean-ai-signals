## 1. 배경

Claude Code 플러그인 [korean-kit](https://github.com/IsthisLee/korean-kit) 에는 한국어 문서를 저장할 때 AI 티가 나는 표현을 짚어 주는 검사 훅이 있었습니다. 그 규칙은 만든 사람의 경험으로 정한 것이라 근거가 약해서 2026-09-17 에 뺐습니다. 근거가 생기면 그 지표로 다시 만듭니다.

2026-09-14 에 규칙을 고치며 한 측정은 근거가 되지 못했습니다. 이유가 셋입니다.

1. 사람이 쓴 글인지를 **파일 수정 연도로 짐작**했습니다. 실제 작성자는 확인하지 않았습니다.
2. 규칙을 빼는 변경에 「사람 글 오탐이 늘지 않을 것」이라는 기준을 썼습니다. 규칙을 빼면 걸리는 글은 줄기만 하므로 **떨어질 수 없는 기준**이었습니다.
3. 합격선을 **결과를 본 뒤에** 적었습니다.

그래서 작성자가 확인된 사람 글과 같은 주제의 AI 글을 모아 비교하고, 기준을 결과보다 먼저 적기로 했습니다. 그 계획으로 파일럿을 두 번 돌렸고, 결과를 보고 설계에서 고칠 곳이 드러나 이 문서로 다시 썼습니다.

## 2. 이미 있는 연구

한국어 AI 글을 가려내는 연구는 이미 있습니다. 2026-09-17 에 원문을 열어 확인했습니다.

| 연구 | 무엇을 했나 | 공개 |
| --- | --- | --- |
| KatFishNet (ACL 2025) | 에세이·시·논문 초록 세 장르에서 사람 글 470편과 LLM 글 1,624편을 모아, 띄어쓰기·품사 다양도·쉼표로 가려냄. 모델 넷(GPT-4o, Solar, Qwen2 72B, Llama3.1 70B) | 코드와 자료 공개 |
| 비지도 탐지 (EACL 2026 Findings) | 한국어 짝 자료 1,000쌍을 만들고, 글을 모델에게 다시 쓰게 해 비교하는 방법으로 F1 0.963, ROC-AUC 0.985 | 코드 공개 |

**그래서 「한국어 AI 글 검출기를 새로 만든다」는 목표는 세우지 않습니다.** 이미 더 좋은 것이 있습니다. 대신 아무도 확인하지 않은 것을 묻습니다.

## 3. 이 분석이 묻는 것

- **Q1. 전이되는가.** 에세이·시·논문 초록에서 통한 지표가 **블로그와 기술 문서**에서도 통하는가. 방향이 뒤집히는 지표는 무엇인가.
- **Q2. 작성자 때문인가.** 사람 글과 AI 글의 차이가 정말 작성자 때문인가, 아니면 시대·추출 방식·글 길이 때문인가.
- **Q3. 규칙으로 옮길 수 있는가.** 통하는 지표 가운데 정규식으로 셀 수 있는 것이 있는가. 그 규칙이 사람 글을 잘못 잡지 않는가.

Q3 이 플러그인과 직접 이어집니다. Q1 과 Q2 는 Q3 의 답을 믿을 수 있게 만드는 준비입니다.

## 4. 용어 풀이

처음 보는 말이 나오면 여기로 돌아오십시오.

| 말 | 뜻 |
| --- | --- |
| **코퍼스** | 분석하려고 규칙을 정해 모아 둔 글 뭉치입니다. 아무 글이나 많이 모은 것과 다릅니다 |
| **지표** | 글 한 편에서 세는 숫자입니다. 「쉼표가 든 문장의 비율」처럼 값 하나로 나옵니다 |
| **짝 설계** | 사람 글 하나와 AI 글 하나를 **같은 제목**으로 묶어 비교하는 방식입니다. 주제가 다르면 주제 탓인지 작성자 탓인지 가릴 수 없어서 이렇게 합니다 |
| **오탐** | 사람이 쓴 글을 AI 글이라고 잘못 잡는 것입니다. 이 분석에서 가장 피하려는 실수입니다 |
| **문턱** | 점수가 이 값을 넘으면 AI 글로 본다고 정한 경계입니다 |
| **AUROC** | 사람 글 하나와 AI 글 하나를 임의로 뽑았을 때 AI 글의 점수가 더 높은 비율입니다. 0.5 는 동전 던지기, 1 은 언제나 맞힘입니다 |
| **기준선** | 비교 대상입니다. 「글자 수만 세면 얼마인가」를 옆에 놓아야 우리 방법이 좋은지 알 수 있습니다 |
| **대응 표본 검정** | 짝지은 자료를 비교하는 통계 방법입니다. 짝 안의 차이만 보므로 주제 차이가 끼어들지 않습니다. 여기서는 Wilcoxon 부호순위 검정을 씁니다 |
| **효과 크기** | 차이가 얼마나 큰지를 나타내는 값입니다. 「차이가 있다」와 「차이가 크다」는 다릅니다 |
| **신뢰구간** | 값이 놓일 만한 범위입니다. 점 하나만 적으면 그 값이 얼마나 흔들리는지 알 수 없습니다 |
| **다중 비교 보정** | 지표를 40개 재면 우연히 차이가 나는 것이 섞입니다. 그만큼 기준을 엄하게 하는 계산입니다. 여기서는 Benjamini-Yekutieli 방법을 씁니다 |
| **훈련·개발·시험** | 자료를 셋으로 나눕니다. 훈련으로 만들고, 개발로 조정하고, **시험은 끝까지 손대지 않았다가 마지막에 한 번만** 씁니다 |
| **사전 등록** | 결과를 보기 전에 기준을 적어 공개하는 일입니다. 이 문서가 그것입니다 |

## 5. 자료

### 5.1 사람 글

**규칙.** ChatGPT 가 공개된 2022-11-30 **이전**에 쓰인 글만 씁니다. 그 전 글에는 AI 가 쓴 글이 섞일 가능성이 거의 없습니다.

| 장르 | 모은 편수 | 출처와 규칙 |
| --- | --- | --- |
| 위키백과 | 300편 | 무작위 문서의 기준일 이전 마지막 판. 본문 문단만 뽑음 |
| 기업 기술 블로그 | 129편 | 한국어 기업 기술 블로그 목록에서 회사마다 15편까지 |
| 개인 블로그 | 58편 | 개발 블로그 목록에서 필자마다 한 편 |

블로그 글은 **Common Crawl** 이 기준일 전에 수집해 둔 사본에서 본문을 뽑습니다. 수집 시각이 게시일의 상한이 되므로, 나중에 고친 글이 섞이지 않습니다. 번역 표시가 있는 글과 번역 위주 블로그는 뺍니다. 정리한 뒤 한글 800자 이상인 글만 씁니다.

**기술 블로그를 129편에서 접습니다.** 표본 틀 83곳 가운데 아직 열어 보지 못한 회사에 남은 수집본이 26개뿐이고, 수집본이 많은 회사를 열어도 대부분 800자 미만이거나 글 쪽이 아니었습니다. 150편을 채우려면 몇 주가 더 걸리고 얻는 것이 적습니다.

**개인 블로그를 58편에서 접습니다.** 2026-09-17~18 에 색인이 열릴 때마다 열 판을 돌렸지만 한 편도 받지 못했습니다. 색인 서버가 응답하다 끊기고, 필자별 질의는 대부분 30초 안에 답하지 않았습니다. 대안으로 각 블로그의 RSS 와 사이트맵을 살폈지만 사이트맵에는 게시일이 없고 `lastmod` 가 조회 시각으로 찍히며, RSS 는 최신 글만 줍니다. Wayback Machine 은 확인한 시점에 서비스가 내려가 있었습니다. 게시일의 상한을 보증할 경로가 없어 지금 모은 58편으로 확정합니다.

**최종 규모는 사람 글 487편**입니다(위키 300, 기술 129, 개인 58).

### 5.2 AI 글

사람 글 한 편마다 **같은 제목, 같은 장르, 비슷한 분량**으로 Claude 가 한 편씩 씁니다. 모두 487편입니다.

- 모델은 claude-opus-5 와 claude-sonnet-5 를 장르 안에서 번갈아 씁니다.
- 사용자 설정과 도구를 끈 상태로 만듭니다. 기본 시스템 프롬프트는 그대로 둡니다. 이 플러그인이 다루는 것이 Claude Code 가 쓰는 글이기 때문입니다.
- **프롬프트 민감도 확인:** 제목 100개에는 두 번째 프롬프트(분량 지정 없음)로도 한 편씩 더 만듭니다. 결과가 프롬프트 형태에 얼마나 좌우되는지 보기 위해서입니다.

**목록에 수집본 위치를 함께 적습니다.** 색인 서버가 불안정해서 주소만으로는 같은 글을 다시 받지 못할 수 있기 때문입니다(WARC 파일 이름, 위치, 길이, 내용 해시).

## 6. 재는 것

### 6.1 주 분석: 검증된 지표 8개

KatFishNet 이 한국어 자료에서 확인한 지표만 주 분석으로 씁니다.

| 번호 | 지표 | 연구가 보고한 방향 |
| --- | --- | --- |
| 1~5 | 쉼표가 든 문장 비율, 쉼표 사용률, 쉼표의 문장 안 위치, 쉼표로 나뉜 구간 길이, 쉼표 앞뒤 품사 쌍 다양성 | AI 가 높음 |
| 7 | 띄어쓰기 규칙 준수도 | AI 가 높음 |
| 8 | 어휘 다양도 | 연구끼리 엇갈림 |
| 11 | 품사 n-gram 다양성 | 사람이 높음 |

### 6.2 쓰지 않기로 한 후보

처음에는 영어·일본어 연구와 한국어 번역문 연구에서 후보를 35개 더 모았습니다. **지금은 쓰지 않습니다.** 이유는 둘입니다.

1. **한국어 AI 글에서 확인된 적이 없습니다.** 다른 언어의 문법 특징을 한국어 표지로 옮기는 과정에 우리 판단이 들어갔습니다.
2. **파일럿에서 살아남지 못했습니다.** 지표 40개를 같은 자격으로 검정했더니 보정을 넘긴 것이 1차에서 5개, 길이를 맞추면 1개, 2차에서는 0개였습니다. 살아남은 것은 대부분 위 8개 안에 있었습니다. 수치는 `results/pilot` 과 `results/pilot2` 의 JSON 에 있습니다.

분석 도구는 이 값들을 함께 계산하지만, 결과 문서에 해석을 달지 않고 판정 근거로도 쓰지 않습니다.

## 7. 비교하는 방법

### 7.1 짝을 살려서 비교합니다

사람 글과 AI 글은 같은 제목으로 짝지어져 있으므로, **짝 안의 차이**를 봅니다.

- 검정: Wilcoxon 부호순위 검정
- 함께 적는 값: 효과 크기와 95% 신뢰구간
- 여러 지표를 한꺼번에 보므로 Benjamini-Yekutieli 보정을 합니다

처음에는 두 묶음을 따로 놓고 비교하는 검정을 썼습니다. 짝을 버리는 방식이라 주제 차이가 그대로 섞였습니다.

### 7.2 기준선 셋과 견줍니다

우리 결과가 좋은지 나쁜지 말하려면 비교 대상이 필요합니다.

1. **글자 수 하나로 판정**했을 때의 AUROC
2. **KatFishNet 지표 8개**만으로 만든 점수
3. **형태소 빈도에 로지스틱 회귀**를 학습시킨 점수(교차 검증)

### 7.3 교차 확인

- 우리 점수를 **KatFish 자료**(공개된 사람 글 470편, LLM 글 1,624편)에 돌립니다.
- KatFishNet 지표를 **우리 자료**에 돌립니다.

양쪽에서 통한 지표만 믿습니다. 한쪽에서만 통하면 장르나 표본에 따라 달라지는 값입니다.

### 7.4 표본이 멀쩡한지 점검합니다

우리가 만든 Claude 글이 평범한 AI 글인지 확인합니다. 공개된 비지도 탐지 방법(EACL 2026)을 우리 AI 글에 돌려, 그 방법이 잘 잡아내면 정상입니다. 잘 잡지 못하면 우리 생성 방식이 특이하다는 신호이므로 프롬프트부터 다시 봅니다.

이 방법은 모델 호출이 필요하므로, 접근이 안 되면 못 했다고 적습니다.

### 7.5 통제 실험 셋

차이가 작성자 때문인지 확인하는 장치입니다.

| 무엇을 의심하나 | 어떻게 확인하나 |
| --- | --- |
| **시대**: 사람 글은 2022년 이전, AI 글은 2026년 | 사람 글끼리 연도로 갈라 같은 점수를 매깁니다. 사람끼리도 갈리면 그 점수는 시대를 재고 있는 것입니다 |
| **추출 방식**: 사람 글은 HTML 에서 뽑고 AI 글은 모델 출력 그대로 | AI 글을 HTML 로 감쌌다가 같은 추출기로 되뽑아 지표가 얼마나 흔들리는지 잽니다 |
| **길이 맞춤**: 긴 쪽을 자르면 대개 사람 글의 끝이 잘림 | 맞춤 전후 두 값을 모두 보고합니다 |

## 8. 성공과 실패의 기준

결과를 보기 전에 정합니다.

**Q1(전이)의 판정**

- 주 분석 8개 지표 가운데 **보정 뒤에도 유의하고 효과 크기 신뢰구간이 0을 포함하지 않는 지표**가 몇 개인지 셉니다.
- 연구가 보고한 방향과 같은지 지표마다 적습니다. 방향이 뒤집힌 지표는 따로 강조해 보고합니다.

**Q3(규칙)의 판정**

- 후보 규칙마다 문턱을 정하고(9절), **훈련·개발 사람 글에서 잡힌 글이 0편**이며 **개발 AI 글에서 1편 이상** 잡힌 것만 남깁니다.
- 남은 규칙 묶음을 **시험 자료에 한 번만** 적용해 오탐률을 재고, 정확 신뢰구간과 함께 보고합니다.

**가르지 못했을 때**

지표가 하나도 남지 않거나 규칙이 하나도 채택되지 않아도 그 결과를 그대로 적습니다. 그 경우의 결론은 「지금 표본과 방법으로는 규칙을 만들 근거가 없다」이고, 플러그인에서는 근거 없는 규칙을 빼는 쪽으로 반영합니다.

## 9. 검사 훅 규칙을 정하는 법

플러그인의 검사 훅은 형태소 분석기 없이 정규식으로만 돕니다. 그래서 규칙 후보는 글자에서 셀 수 있어야 합니다.

- **후보 1:** 지금 규칙(K1~K4, K6~K8). K8 은 항목 셋을 따로 봅니다.
- **후보 2:** 주 분석에서 살아남은 지표 가운데 정규식으로 옮길 수 있는 것.
- **후보 3:** 훈련 표본에서 뽑은 표현. 글을 공백으로 나눈 어절의 1~3-gram 가운데 Claude 글 쪽으로 치우친 것을 골라 문자열 그대로 씁니다.

**문턱:** 후보마다 훈련 사람 글에서 한 편에 가장 많이 나온 횟수에 1을 더한 값입니다.

**적용 대상 확인:** 채택한 규칙을 플러그인 저장소의 한국어 문서에도 돌려 오탐을 잽니다. 수집한 블로그 글과 실제 작업 문서는 문체가 다르기 때문입니다.

**알림 문구:** 규칙이 걸렸을 때 보여 주는 안내는 뜻을 지우지 않게 씁니다. 안내를 바꾸면 고친 글에서 사실과 문장 성분이 빠지지 않는지 따로 잽니다.

## 12. 한계

1. **모델 한 계열.** Claude 만 씁니다. 다른 모델의 글에서 같은 결과가 나온다고 말할 수 없습니다.
2. **시대 교란.** 사람 글은 2022년 이전, AI 글은 2026년입니다. 통제 실험으로 크기를 재지만 없앨 수는 없습니다.
3. **장르 치우침과 얇은 칸.** 개인 블로그 표본 틀이 개발자 블로그 목록이라 주제가 개발에 치우칩니다. 게다가 개인 블로그가 58편뿐이라 이 칸이 다른 두 장르보다 얇습니다. 장르별로 나눠 볼 때 효과가 작으면 놓칠 수 있습니다.
4. **수집 결측이 무작위가 아닙니다.** 색인 오류로 빠진 회사가 특정 호스트에 몰렸습니다. 결측 분석표를 함께 냅니다.
5. **판정자 편향.** 뜻 손실과 명확성을 Claude 가 판정합니다. 일부를 사람이 대조해 줄입니다.
6. **선택 뒤에는 보장이 약해집니다.** 후보를 여럿 놓고 고르면 우연히 통과한 규칙이 섞입니다. 시험 자료를 마지막 한 번만 쓰는 이유가 이것입니다.
